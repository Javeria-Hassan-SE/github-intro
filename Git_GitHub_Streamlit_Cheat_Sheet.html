Start here

Five words you will hear all day.

Git

A program on your laptop. It remembers every version of your project folder, like "save" with a full history.

GitHub

A website that stores your Git projects online. It is your backup, your portfolio and the place Streamlit reads your code from.

Repository (repo)

A project folder that Git is watching. It has your files plus a hidden .git folder that holds the history. Never delete .git.

Commit

One saved snapshot with a short message, like "Add sales chart". You choose when to take it.

Push and pull

Push sends your commits up to GitHub. Pull brings new commits down to your laptop.

Three rules to take care of
  • Run git status before every add, commit and push. It is read only and tells you the truth.
  • Never commit passwords, API keys, tokens or your venv folder. Anything pushed to a public repo is public, even if you delete it later.
  • Commit small and often, with a message that says what changed.

"Publishing" a repo: two different meanings

A. Make the code public

Settings → General → scroll to Danger Zone → Change visibility → Make public. Confirm the prompts. Anyone with the link can read your code.

Before you do this, check that no password or key is inside your files.

B. Publish a website (GitHub Pages)

  1. Repo has an index.html in the main folder.
  2. Settings → Pages.
  3. Build and deployment → Source: Deploy from a branch.
  4. Branch: main, folder: / (root) → Save.
  5. Wait one or two minutes. The link appears at the top: https://username.github.io/repo-name/
Take care

GitHub Pages can only host static files (HTML, CSS, JavaScript, images). It cannot run Python, so a Streamlit app does not run there. Streamlit apps go to Streamlit Community Cloud (chapter 9).

2. Install Git and set it up (Windows)

Do this once per laptop.

  1. Download Git for WindowsGo to git-scm.com and download the Windows installer.
  2. Run the installerClick Next through the screens. The default choices are fine. Keep Git Credential Manager ticked, it handles your GitHub sign-in. If it asks for the default editor, choose Visual Studio Code.
  3. Open a new terminal and checkSearch for Command Prompt (or PowerShell, or Git Bash). Close any old terminal first, because an old one does not know about Git yet. 
    git --version
    You should see something like git version 2.4x.x.windows.1.
  4. Tell Git who you are (one time)This name goes into every commit you make. 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
    Email privacy

    Commit emails become public on public repos. In GitHub go to Settings → Emails, tick Keep my email addresses private, and use the address that looks like 12345+username@users.noreply.github.com in the command above.

  5. Check your settings 
    git config --list

How every Git command is built

git  commit  -m  "Add chart"
 │     │      │       └─ the value for the option
 │     │      └─ option (starts with - or --)
 │     └─ the action
 └─ the program

Windows tip: put quotes around names that contain spaces, for example git add "Sales Data.csv". Better still, avoid spaces in file names.

3. Work on your laptop: three ways

All three do the same job and talk to the same GitHub repo. Choose the one that looks easiest. You can mix them.

A. With CMD commands

Path 1: the repo already exists on GitHub (clone)

  1. Go to the folder where projects should live 
    cd Documents
mkdir projects
cd projects
    writes for mkdir, the rest is read only.
  2. Clone the repoPaste the link from the green Code button (HTTPS tab). 
    git clone https://github.com/username/sales-dashboard.git
    writes Creates a new folder sales-dashboard and downloads all files and history. Run it outside any other repo.
  3. Go inside and open VS Code 
    cd sales-dashboard
code .
  4. Edit your files, then look at what changed 
    git status
git diff
    read only status lists changed files. diff shows the exact lines.
  5. Stage the files you want in the snapshot 
    git add app.py
git add .
    writes The first adds one file. The dot adds everything that changed. Check git status first so you do not add junk.
  6. Commit 
    git commit -m "Add monthly sales chart"
    writes Saves the snapshot on your laptop only. Always use -m with a message, otherwise Git opens an editor that confuses beginners.
  7. Push to GitHub 
    git push
    remote Sends your new commits to GitHub. Refresh the repo page to see them.
  8. Next day: pull before you start 
    git pull
    remote Brings new commits from GitHub, for example edits you made on the website.

Path 2: the project exists on your laptop first (init + connect)

  1. Create an empty repo on GitHubOn the website, create the repo without README and without .gitignore, so it starts empty. Copy its link.
  2. Turn your folder into a repo 
    cd path\to\sales-dashboard
git init
git branch -M main
    writes init creates the hidden .git folder. branch -M main makes sure the branch is named main.
  3. Create .gitignore nowBefore the first add. See the .gitignore table in Advanced.
  4. First snapshot 
    git status
git add .
git commit -m "First commit"
  5. Connect to GitHub and push 
    git remote add origin https://github.com/username/sales-dashboard.git
git push -u origin main
    origin is just the nickname for the GitHub link. -u remembers it, so later you can type only git push and git pull.

6. Advanced

When you work with other people, or want to experiment safely.

Create a plain text file named exactly .gitignore in the main folder. One pattern per line. Make it before your first git add .. A file Git already tracks is not hidden by adding it here later (see Fix errors).

Branches: a safe copy to experiment on

A branch is a separate line of commits. main stays clean while you try something on a branch. If it works, merge it. If not, delete it.

git switch -c add-filters      # make a branch and move to it
# edit, add, commit as usual
git push -u origin add-filters # first push of this branch
git switch main                # go back
git merge add-filters          # bring the work into main
git branch -d add-filters      # delete the finished branch
Take care

Before git switch, commit or stash your edits. Switching changes the files in your folder to match the other branch.

Pull request (PR): ask to merge on GitHub

  1. Push your branchgit push -u origin add-filters
  2. Open the repo on GitHubA yellow banner appears: Compare & pull request. Click it. (Or Pull requests tab → New pull request.)
  3. Describe itWrite a title and a short description of what changed and why. Choose the base branch (main) and your branch.
  4. Create pull requestThe page shows the files changed. A teammate can comment or approve.
  5. MergeClick Merge pull request then Confirm. Then Delete branch.
  6. Update your laptop 
    git switch main
git pull

Fork vs clone

A clone is a copy on your laptop. A fork is a copy of someone else's repo inside your GitHub account (button at the top right of their repo). You fork when you do not have permission to push to the original. Then you clone your fork, make a branch, push, and open a PR to the original.

Fix a merge conflict step by step

  1. Do not panicA conflict means Git cannot decide between two edits to the same lines. Nothing is lost. git status lists the files marked both modified.
  2. Open the file in VS CodeYou see markers. Between <<<<<<< HEAD and ======= is your version. Between ======= and >>>>>>> is theirs. VS Code shows buttons above: Accept Current, Accept Incoming, Accept Both.
  3. Choose, then remove all marker linesThe final file must have no <<<<<<<, ======= or >>>>>>> left. Save.
  4. Finish 
    git add README.md
git commit -m "Fix merge conflict in README"
git push
  5. Want to cancel?git merge --abort puts everything back as it was before the pull. (If you used git pull with the default setting and it was a merge, this works.)

Stash: put edits in a drawer for a moment

git stash          # hide my unfinished edits, folder becomes clean
git switch main    # do something else
git stash pop      # bring the edits back

git stash list shows what is in the drawer (read only).

Take care

Never use git push --force on shared branches. It overwrites other people's commits on GitHub. If you must, use --force-with-lease, which refuses if someone else pushed in the meantime.

Tags and releases

git tag v1.0
git push origin v1.0

A tag is a name for one commit, like a bookmark. On GitHub, the Releases area (right side of the Code tab) can turn a tag into a downloadable version.

Habits of a good commit

  • One idea per commit.
  • Message starts with a verb: "Add city filter", "Fix date parsing", "Update README".
  • Not "update", "final", "aaa", "changes".

7. Signing in to GitHub from your laptop

GitHub does not accept your account password in Git. These are the ways that work.

A. Browser sign-in (easiest)

With Git for Windows, the first git clone of a private repo or git push opens a window titled Git Credential Manager. Choose Sign in with your browser and approve. Windows remembers it. VS Code and GitHub Desktop do the same through their own sign-in buttons.

B. Personal access token

GitHub → your photo → Settings → Developer settings → Personal access tokens → generate one with access to your repo. When Git asks for a password, paste the token. Copy it when it is shown, because GitHub shows it only once.

danger A token works like a password. Never put it in code or a README.

C. SSH key (advanced)

ssh-keygen -t ed25519 -C "you@example.com"

Press Enter to accept the defaults. Copy the contents of the .pub file into GitHub → Settings → SSH and GPG keys. Then clone with the link that starts with git@github.com:.

Use the right link

On the green Code button, the HTTPS tab gives https://github.com/... and the SSH tab gives git@github.com:.... For beginners, use HTTPS.

9. Deploy a Streamlit app (Community Cloud)

Your code goes to GitHub, then Streamlit builds it and gives you a public link such as https://your-app-name.streamlit.app. It is free.

Checklist before you deploy

  • App runs on your laptop: streamlit run app.py.
  • requirements.txt lists every package the app imports (not Python built-ins).
  • The data file is in the repo, and its name matches your code exactly, including capital letters. Streamlit runs on Linux where Sales Data.csv and sales data.csv are different files.
  • The code uses relative paths like "Sales Data.csv". Not C:\Users\.... That path does not exist on the server.
  • venv/ and secrets are in .gitignore.
  • Everything is committed and pushed. Open the repo on GitHub and confirm the files are there.

Version pins

Writing streamlit>=1.30,<1.50 means "any version from 1.30 up to but not including 1.50". It keeps your app from breaking when a new Streamlit changes behaviour. Put one package per line, no extra spaces.

Take care with big data

GitHub blocks files over 100 MB and warns above 50 MB. The sales file (22 MB) is fine. The COVID file (about 98 MB) is too close to the limit, so read it from its web link instead: pd.read_csv("https://…/owid-covid-data.csv").

Deploy step by step

  1. Open Streamlit Community CloudGo to share.streamlit.io and choose Continue with GitHub. Allow Streamlit to access your account when GitHub asks.
  2. Create appClick Create app (top right) and choose Deploy a public app from GitHub. (If you picked the option to start from a template, go back and choose the GitHub one.)
  3. Fill the three boxes
    BoxWhat to enter
    Repositoryusername/sales-dashboard, or pick it from the list
    Branchmain
    Main file pathapp.py. If the file is inside a folder, write the folder too: sales_dashboard/app.py.
    App URL (optional)Choose a short name, for example my-sales-dashboard.
  4. Advanced settings (only if needed)Open Advanced settings to choose the Python version and to paste Secrets (see below). For our sales dashboard you can skip this.
  5. Click DeployA page shows the build log. The first run installs your packages from requirements.txt, which takes a few minutes. When it finishes, your app opens at its own link.
  6. ShareCopy the link into your assignment or your portfolio. Add it to your repo's README.md too.

Update the app later

git add .
git commit -m "Add city filter"
git push

Streamlit watches the repo. After the push, the app updates by itself in a short time. If you changed requirements.txt it installs the packages again.

Secrets: passwords and API keys

Never write a key inside app.py. Use Streamlit secrets.

On your laptop: file .streamlit/secrets.toml
API_KEY = "paste-your-key-here"

Add .streamlit/secrets.toml to .gitignore so it never reaches GitHub.

In app.py
import streamlit as st
key = st.secrets["API_KEY"]

On the server: Advanced settings → Secrets, paste the same line. After deploy: ⋮ → Settings → Secrets.

Troubleshooting

Problem in the logReasonFix
ModuleNotFoundError: No module named 'plotly'The package is not in requirements.txt.Add it, commit, push.
FileNotFoundError: … Sales Data.csvFile not pushed, or different name or capital letters, or a Windows path.Check the file is on GitHub with the exact name. Use a relative path.
"This file does not exist" for the Main file pathWrong path or wrong branch.Edit the app settings. Include folder names in the path.
Install fails with "No matching distribution"A pinned version does not exist for the chosen Python version.Loosen the pin, or choose another Python version in Advanced settings.
App is slow or restarts ("resource limits")The free server has limited memory. Big data loaded again and again.Use @st.cache_data on the loading function, drop unused columns, use a smaller file.
Works on laptop, fails on serverDifferent package versions, or a file only on your laptop.Pin versions in requirements.txt. Run pip freeze to see what you have installed.
Linux cannot find a system toolSome packages need a system library.Add a file named packages.txt with the system package names, one per line. Not needed for our dashboards.

Before you click push: final check

  • git status shows only files I expect.
  • No venv, .env, keys or passwords in the list.
  • The commit message says what changed.
  • I pulled first if I also edited online or work with a partner.
